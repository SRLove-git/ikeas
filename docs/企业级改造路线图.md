## 横切事项（贯穿全程）

- 每个重大选型（JWT 方案、消息队列、Redis 用法、微服务拆分）先写 ADR 再实施。
- 数据/接口变更同步更新 OpenAPI 与 [项目规范.md](项目规范.md)，保持需求、设计、代码一致。
- 所有变更走 `feature/xxx` → PR（≥1 人 Review）→ `develop` → `release/x.y.z` → `main`，禁止直接提交主干。
- 版本号按 SemVer，与镜像 tag、发布分支、发布记录一致。

## 风险与注意事项

- **JSON → 数据库迁移**是本项目最大风险：先做只读兼容层，前台功能回归通过后再下线 JSON 读写。
- 现有代码在 `master` 分支且无测试覆盖，改造期间每一步都要求 `npm run check` + 后端测试通过后再合入。
- 密码与密钥：BCrypt 哈希 + 环境变量/密钥管理，禁止入库；JWT 私钥必须可轮换。
- 若接入支付，需额外完成支付合规、对账、退款链路（列入 3.2 验收）。
