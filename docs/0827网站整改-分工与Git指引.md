## 4. Git 协作指引

### 4.1 分支模型

遵循 `docs/项目规范.md` §6：`main` 为发布分支、`develop` 为集成分支、`feature/xxx` 功能分支、`hotfix/xxx` 缺陷修复。当前仓库仍在 `master` 运行，迁移到 `main/develop` 前，统一以 `master` 为基准。

- 每条问题一条分支，命名带问题编号：`feature/01-https-cert`、`feature/06-guest-checkout`、`hotfix/03-sg-mobile`。
- 禁止直接向 `master` / `develop` / `main` 提交；所有变更走 PR 合并，至少对方 1 人 Review。

### 4.2 每日开工与收工

```bash
# 开工：先同步基准，再切新分支
git fetch origin
git checkout master && git pull --rebase origin master
git checkout -b feature/06-guest-checkout

# 收工前：提交 → 拉最新基准 → 合入自己的分支 → 推送
git pull --rebase origin master
git push -u origin feature/06-guest-checkout
```

合入 PR 前必须把分支 rebase 到最新基准，保持历史线性。

### 4.3 提交信息

遵循 Conventional Commits，类型用 `feat` / `fix` / `docs` / `refactor` / `test` / `chore`，尽量带问题编号：

```text
fix(frontend): 登录页移除测试账号与 IKEA 残留 (#02)
feat(backend): 保修登记接口与登记编号生成 (#05)
feat(data): 商品详情补充 HSA 认证字段 (#08)
```

一个逻辑变更一个 commit，禁止把无关改动混在一起。

### 4.4 目录边界与冲突规避

- 前端改 `frontend/`，后端改 `backend/`、`deploy/`，天然不冲突。
- **共享区只有数据**：`frontend/src/data/` 是唯一编辑入口，`backend/src/main/resources/data/` 由 `node scripts/export-server-data.mjs` 机械生成。
  - 谁改数据谁负责同步并提交两端文件。
  - 两人不要同时改同一个 JSON 文件；改数据前先 `git pull --rebase`。
  - 数据文件冲突时不用手工解决：保留 `frontend/src/data/` 一侧，重跑 export 脚本覆盖副本。
- 接口变更按「契约先行」：后端先出接口文档（路径统一 `/api/v1/`，见项目规范 §3），前端再同步 `frontend/src/lib/api.ts`。后端 PR 先合，前端 PR 基于最新基准 rebase 后合。

### 4.5 协作问题的 PR 拆分

协作项（01、02、03、05、06、13、15、16、19、22、23）允许拆成前端/后端两个 PR：

- 后端 PR 标题带 `(#xx 后端)`，前端 PR 带 `(#xx 前端)`，互相引用方便追踪。
- 两个 PR 都要通过对方 Review；接口契约以先合的那一方为准。
- 同一问题的两个 PR 尽量同一天合并，避免中间状态长期存在于基准分支。

### 4.6 Review 检查点

每个 PR 由另一人 Review，重点检查：

- 商品目录仍为 23 个 BUZUD 商品、价格 SGD、无 IKEA/测试凭据残留。
- 接口出入参与前端 `api.ts` 类型一致；数据字段 camelCase 与后端 Jackson 映射一致。
- 移动端 375×812 实测无遮挡、无横向滚动、无半句字幕。
- 改动无 lint/typecheck/build 报错。

## 5. 验证清单（提交前逐项执行）

```bash
# 前端（frontend/ 下执行）
npm run typecheck && npm run lint && npm run build
npm run format:check        # Prettier 检查，可先 npm run format

# 后端（backend/ 下执行）
./mvnw test                 # 关键模块单测
./mvnw -DskipTests package  # 打包

# 数据改动（仓库根目录执行）
node scripts/export-server-data.mjs   # 同步后端副本
# 重启后端后抽查对应页面/接口
```
